# 모바일 앱 전환 계획

## 현재 상태
- 기존 서비스는 루트의 정적 `index.html`을 Vercel로 배포하는 구조입니다.
- 프레임워크 기반 프로젝트가 아니므로 기존 화면을 최대한 유지하고 Capacitor Android 앱으로 감싸는 방식이 적합합니다.
- 이 브랜치는 기존 `main` 및 `photo-assets-collection`과 분리되어 있습니다.

## 목표 1차 버전
1. 기존 도카이도 일정/사진 화면 유지
2. Android 앱으로 설치 가능한 패키지 생성
3. 걷기 시작/일시정지/종료 버튼
4. 화면이 꺼져도 위치를 기록하는 Android foreground service
5. 위치 기록을 기기에 저장하고 지도에 경로 표시
6. 기록 중 알림 표시, 권한 거부 및 GPS 꺼짐 안내

## 구현 원칙
- 웹 화면의 `navigator.geolocation.watchPosition`만으로 백그라운드 기록을 구현했다고 간주하지 않습니다. Android 네이티브 foreground service와 위치 권한 처리가 필요합니다.
- 위치 기록은 기본적으로 기기에 저장합니다. 서버 업로드는 별도 동의와 설계를 거칩니다.
- Google Maps API 키가 아직 없으므로 지도 공급자는 먼저 결정하지 않습니다. 기록 경로는 좌표를 선으로 연결하는 기능만으로도 표시할 수 있습니다.
- Galaxy Watch9 연동은 1차 버전의 스마트폰 GPS 기록을 검증한 뒤 별도 단계로 진행합니다. 삼성 헬스/Health Connect의 데이터 접근 권한과 동기화 지연을 고려해야 합니다.

## 개발 단계
- [ ] A. Capacitor 프로젝트 뼈대 및 Android 프로젝트 생성
- [ ] B. 기존 웹 화면을 앱 패키지에 포함
- [ ] C. Android 위치 권한과 화면 꺼짐 상태의 foreground tracking 구현
- [ ] D. 기록 경로 저장/복구 및 지도 표시
- [ ] E. 실제 Galaxy 기기에서 화면 꺼짐, 절전, 재실행 테스트
- [ ] F. Galaxy Watch9/Samsung Health 데이터 연동 검토

## 실제 기기 테스트 체크리스트
- 위치 권한: 앱 사용 중 / 항상 허용 여부
- Android 위치 서비스 비활성화 안내
- 화면 잠금 후 30~60분 기록 유지
- 앱 전환 및 앱 프로세스 종료 후 동작 확인
- 배터리 사용량과 위치 정확도
- 일시정지/재개/종료 및 중복 세션 방지
- 기록 내보내기/삭제와 개인정보 안내
